# Política de seguridad / Security policy

## Versiones / Supported versions

La rama `main` y la serie 0.1.x reciben correcciones. No se promete mantenimiento de versiones anteriores ni tiempos de respuesta concretos.

The `main` branch and the 0.1.x series receive fixes. Earlier versions and specific response times are not promised.

## Informar de una vulnerabilidad / Reporting a vulnerability

No publiques un exploit, secreto o vulnerabilidad sin corregir en una incidencia pública. Usa **Security → Report a vulnerability** en GitHub cuando esa opción esté disponible. Si no aparece, abre una incidencia pública con un resumen no sensible solicitando un canal privado; no incluyas pasos de explotación, datos personales ni credenciales.

Do not publish an exploit, secret or unpatched vulnerability in a public issue. Use **Security → Report a vulnerability** on GitHub when available. If it is unavailable, open a public issue with a non-sensitive summary requesting a private channel; do not include exploitation steps, personal data or credentials.

Incluye, cuando sea seguro:

- versión o commit afectado;
- impacto y condiciones necesarias;
- reproducción mínima con datos sintéticos;
- mitigación temporal conocida;
- si el hallazgo ya se compartió con terceros.

When safe, include the affected version or commit, impact and preconditions, a minimal synthetic reproduction, known temporary mitigation, and whether the finding has already been shared elsewhere.

El mantenedor comprobará el alcance antes de afirmar que un problema existe o está corregido. La recepción de un informe no garantiza recompensa, plazo ni aceptación. La divulgación coordinada conservará atribución cuando sea posible y no expondrá datos privados innecesarios.

The maintainer will verify scope before claiming that a problem exists or is fixed. Receiving a report does not guarantee a bounty, deadline or acceptance. Coordinated disclosure will preserve attribution when possible and avoid unnecessary private data.
